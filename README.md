# Место — бронирование переговорных

**Место** — веб-приложение для просмотра переговорных комнат и планирования встреч. В календаре можно выбрать свободный интервал, создать бронирование, изменить его или отменить.

Проект развивается в двух версиях: от автономного приложения с локальным хранением данных до многопользовательского сервиса с общей базой и обновлением расписания в реальном времени.

## Демо и версии

| Версия | Демо | Особенности |
| --- | --- | --- |
| **v2.0.0 — Multiplayer** | [Открыть v2](https://meeting-rooms-v2.vercel.app/) | Общая база PostgreSQL, аккаунты, права доступа, Supabase Realtime |
| **v1.0.0 — Local** | [Открыть v1](https://meeting-rooms-theta.vercel.app/) | Работа без сервера и регистрации, хранение бронирований в `localStorage` |

Исходный код версий зафиксирован тегами [`v1.0.0`](https://github.com/Anaastaasia/meeting-rooms/tree/v1.0.0) и [`v2.0.0`](https://github.com/Anaastaasia/meeting-rooms/tree/v2.0.0). Разработка многопользовательской версии ведётся в ветке `feature/multiplayer`; ветка `master` сохраняет первую версию.

## Возможности

### Расписание

- Просмотр расписания переговорных на выбранную дату.
- Переключение между днями и возврат к текущей дате по Москве.
- Создание бронирования нажатием на свободную ячейку.
- Выбор интервала протягиванием мыши в обоих направлениях.
- Цветовое обозначение переговорных и переход к странице комнаты из календаря.
- Автоматическая прокрутка к ближайшему актуальному временному интервалу.

### Бронирования

- Создание встречи с названием и временем окончания.
- Редактирование и отмена бронирования с подтверждением.
- Просмотр предстоящих встреч.
- Проверка допустимости времени и пересечений.
- Сохранение данных после обновления страницы: локально в v1 и в общей базе в v2.

### Переговорные и интерфейс

- Каталог комнат с фотографиями, вместимостью и оборудованием.
- Фильтрация по вместимости и оборудованию с сохранением параметров в URL.
- Отдельные страницы переговорных с фотогалереей и расписанием.
- Адаптивная вёрстка, клиентская навигация и модальные окна с управлением с клавиатуры.
- Закреплённые заголовки и колонка времени в календаре.

### Дополнительно в v2.0.0

- Регистрация, вход и подтверждение электронной почты через Supabase Auth.
- Просмотр расписания без входа; создание и управление собственными бронированиями — после авторизации.
- Общая база данных PostgreSQL для разных пользователей и устройств.
- Обновление расписания без перезагрузки страницы через Supabase Realtime.
- Ограничение операций с чужими бронированиями с помощью Row Level Security (RLS).
- Защита от конфликтующих бронирований, в том числе при почти одновременных запросах.
- Состояния загрузки, сообщения об ошибках и повторная загрузка данных при сбоях соединения.

## Правила бронирования

- Время работы: **08:00–20:00 по Москве**.
- Шаг расписания: **30 минут**.
- Встреча должна завершаться в день начала.
- Название встречи не может быть пустым.
- Окончание встречи должно быть позже начала.
- Нельзя создавать встречу, время начала которой уже наступило.
- Бронирования одной комнаты не должны пересекаться; соседние интервалы допустимы.

В v2 ограничения доступа и защита от конфликтующих записей дополнительно обеспечиваются на стороне базы данных, а не только интерфейсом.

## Технологии

**Клиент:** React 19, TypeScript 6, React Router 8, Vite 8, CSS.

**Данные и авторизация (v2):** Supabase JS 2, PostgreSQL, Supabase Auth, Realtime, RLS.

**Качество и развёртывание:** Vitest, ESLint, GitHub Actions, Vercel.

## Как устроена v2

1. **React** отображает календарь, формы и страницы переговорных.
2. **Supabase Auth** управляет входом и пользовательской сессией; состояние авторизации предоставляется компонентам через контекст React.
3. **`bookingApi.ts`** содержит операции с бронированиями, выполняемые через клиент Supabase.
4. **PostgreSQL** хранит общее расписание, а **RLS** ограничивает доступ к операциям над записями.
5. **Supabase Realtime** сообщает открытым клиентам об изменениях, чтобы расписание обновлялось без ручной перезагрузки.

Основные файлы и каталоги:

```text
src/
├── components/       # Расписание, формы, карточки и модальные окна
├── contexts/         # Контекст и провайдер авторизации
├── data/             # Данные переговорных и локальные данные
├── lib/              # Клиент Supabase и API бронирований
├── pages/            # Вход, регистрация, каталог и страницы комнат
├── types/            # Типы бронирований
├── utils/            # Даты, валидация, пересечения и локальное хранение
├── App.tsx           # Маршруты и основная логика интерфейса
├── App.css           # Стили приложения
└── index.css         # Базовые стили
```

## Локальный запуск

Для воспроизводимого окружения рекомендуется **Node.js 24**.

### v1.0.0 — без сервера

```bash
git clone https://github.com/Anaastaasia/meeting-rooms.git
cd meeting-rooms
npm ci
npm run dev
```

По умолчанию клонируется ветка `master` с первой версией. Открой адрес, который Vite покажет в терминале.

### v2.0.0 — с Supabase

```bash
git clone https://github.com/Anaastaasia/meeting-rooms.git
cd meeting-rooms
git switch feature/multiplayer
npm ci
```

Создай в корне проекта файл `.env.local`:

```dotenv
VITE_SUPABASE_URL=адрес_проекта_supabase
VITE_SUPABASE_PUBLISHABLE_KEY=публичный_ключ_supabase
```

Затем запусти:

```bash
npm run dev
```

**Важно:** для самостоятельного развёртывания v2 необходимо предварительно настроить проект Supabase: таблицу `bookings`, авторизацию, политики RLS, ограничения бронирования и Realtime. Переменных окружения недостаточно для создания схемы базы данных. Не помещай секретные ключи в переменные с префиксом `VITE_`: они доступны клиентскому приложению. Файлы `.env` и `.env.local` не следует коммитить.

## Тестирование

В проекте есть модульные тесты логики пересечений бронирований (`src/utils/bookingConflicts.test.ts`), включая пересекающиеся и соседние интервалы, разные комнаты и редактирование существующей встречи.

Для опубликованной v2 вручную проверены вход и сохранение сессии, создание, изменение и отмена бронирований, обновление расписания между двумя аккаунтами и конфликт одновременного бронирования. Эти проверки не заменяют автоматизированные интеграционные тесты.

В репозитории также используется GitHub Actions для автоматических проверок; актуальную конфигурацию следует смотреть в `.github/workflows/` соответствующей ветки.

## Ограничения и различия версий

**v1.0.0:** бронирования хранятся в `localStorage` под ключом `meeting-room-bookings`. У разных браузеров и устройств независимые расписания; очистка данных сайта удаляет локальные бронирования. Нет авторизации, общей базы и серверного разграничения прав.

**v2.0.0:** для работы с бронированиями требуется доступ к настроенному Supabase-проекту и подключение к сети. Расписание общее для пользователей, а управление записями ограничено правами доступа.

Протягивание интервала в календаре реализовано для мыши; отдельная поддержка аналогичного сенсорного жеста не заявлена.
